# 설계: title 페이지와 연습 모드 (사람 vs AI 오목)

## 의도와 이유

오목 토너먼트 서비스의 첫 단계로, title 페이지와 연습 모드를 만든다. 연습 모드는 사람이 화면에서 직접 AI와 오목을 두는 모드이다. 학습자가 오목 규칙과 전략 감각을 익히는 것이 목적이고, 동시에 이후 토너먼트에서 그대로 쓸 규칙 엔진과 오목판 컴포넌트를 먼저 검증하는 역할도 한다.

학습자가 제출하는 Python 코드는 토너먼트에서만 쓴다. 연습 모드는 Python과 무관하다.

## 목표

- title 페이지에서 연습 모드로 이동할 수 있다.
- 사람이 AI(상, 중, 하)를 골라 한 판을 끝까지 둘 수 있다.
- 규칙 엔진이 화면과 분리되어 있어서 토너먼트 구현에서 재사용할 수 있다.
- AI 난이도가 실제로 체감되고, 난이도 순서(상 > 중 > 하)가 테스트로 확인된다.

## 목표가 아닌 것

- 토너먼트 모드, Supabase, 관리자 기능, Python 실행(Pyodide)은 이번 범위가 아니다. title 페이지의 토너먼트 버튼은 "준비 중"으로 비활성화한다.
- 무르기, 대국 저장, 전적 기록, 온라인 대전은 만들지 않는다.
- (변경됨) 이 설계 당시에는 렌주 룰을 범위 밖으로 두었으나, 이후 요청으로 금수(장목, 사사, 삼삼)를 구현했다. `game_rules.md`와 `src/engine/forbidden.ts`를 따른다.

## 피해야 할 결과

- 규칙 판정이 React 컴포넌트 안에 섞여 토너먼트에서 재사용할 수 없게 되는 것
- 상 난이도 계산 중 화면이 멈추는 것
- 난이도 차이가 거의 없어서 하, 중, 상이 비슷하게 느껴지는 것

## 제약

- React, Vite, TypeScript로 작성한다. (`CLAUDE.md`)
- 규칙은 `game_rules.md`를 따른다: 15×15, 렌주 룰(흑은 정확히 5목만 승리하고 장목·사사·삼삼 금지, 백은 5목 이상 승리), 흑 선공, 흑백은 코인 던지기, 판이 가득 차면 백 승리.
- 브라우저에서만 동작한다. 서버가 없다.
- 프로젝트 폴더에는 문서만 있고 코드는 없다. Git 저장소가 아니다.

## 접근 방식

1. **엔진을 화면과 분리 (선택)**: 규칙 엔진과 AI는 순수 TypeScript 모듈로, React는 화면만 담당한다. 토너먼트에서 엔진을 그대로 쓸 수 있다. 처음에 파일이 조금 더 많다.
2. AI도 Python으로 작성해 Pyodide로 실행: 학습자 코드와 같은 방식이지만 로딩이 무겁고 연습 모드 체감이 나빠서 제외했다.
3. 규칙과 AI를 오목판 컴포넌트 안에 모두 작성: 가장 빠르지만 토너먼트 때 엔진을 다시 분리해야 해서 제외했다.

선택한 방식은 1번이다. 이 선택은 사용자가 "가장 좋은 방향으로"라고 맡긴 것이어서 내가 고른 것이다.

## 설계

### 구조

```
src/
  engine/        순수 TypeScript. React에 의존하지 않는다.
    types.ts       Cell, Color, Move, Board 타입
    board.ts       빈 판 만들기, 착수, 복사
    rules.ts       유효한 수 검사, 오목 판정(이긴 줄 좌표 포함), 판이 가득 찼는지
    game.ts        한 판의 진행(차례, 승자 결정, 착수 기록)
  ai/            순수 TypeScript.
    types.ts       AI 인터페이스: (board, color) => Move
    evaluate.ts    패턴 점수 계산 (중, 상이 공유)
    easy.ts, medium.ts, hard.ts
    hard.worker.ts 상 난이도를 Web Worker에서 실행하는 진입점
  ui/            React
    App.tsx        title 페이지 ↔ 연습 모드 화면 전환
    TitlePage.tsx
    PracticePage.tsx
    Board.tsx      오목판 (연습/토너먼트 공용)
```

화면 전환은 상태 하나로 처리하고, 라우터 라이브러리는 쓰지 않는다. 토너먼트 구현 시 필요해지면 그때 도입한다.

### 엔진

- 판은 15×15 2차원 배열이고 `0`은 빈 칸, `1`은 흑, `2`는 백이다. (절대 색 기준. 토너먼트에서 학습자 코드에 넘기는 "내 돌/상대 돌" 관점은 나중에 변환하는 어댑터로 처리한다.)
- 승리 판정은 방금 둔 돌을 기준으로 가로, 세로, 대각선 두 방향을 검사하고, 이긴 줄의 좌표를 함께 반환한다. (UI 강조용)
- 흑백 결정에 쓰는 난수는 주입할 수 있게 해서 테스트에서 고정한다.

### AI 난이도

공통 인터페이스는 `(board, color) => Move`이다.

- **하:** 즉시 오목을 완성할 수 있으면 완성하고, 상대가 즉시 오목을 완성하게 되면 막는다. 그 외에는 놓인 돌 주변 칸 중 무작위로 둔다. 첫 수는 판 중앙 근처에 둔다.
- **중:** 후보 칸마다 공격 점수(내 돌 연결 형태)와 수비 점수(상대 돌 연결 형태)를 합산해 가장 높은 칸을 고른다. 점수는 연결 길이와 열림/막힘 정도(예: 열린 4, 열린 3, 막힌 4)로 매긴다. 동점이면 무작위로 고른다.
- **상:** Minimax에 알파-베타 가지치기를 적용한다.
  - 후보 칸은 기존 돌에서 2칸 이내로 제한하고, 중 난이도의 점수로 정렬해 가지치기 효율을 높인다.
  - 반복 심화로 홀수 깊이(3, 5)를 시간 제한(약 1.5초) 안에 가능한 만큼 깊게 본다. 최대 깊이 5. (구현 중 변경: 짝수 깊이는 같은 시간에 더 약했다)
  - 평가 함수는 `evaluate.ts`의 패턴 점수를 재사용한다.
  - Web Worker에서 실행해 화면이 멈추지 않게 한다.

### 화면

- **title 페이지:** 게임 이름, "연습 모드" 버튼, "토너먼트" 버튼(준비 중, 비활성화).
- **연습 모드 화면:**
  - 시작 전: 난이도(하, 중, 상) 선택.
  - 대국 시작 시 코인 던지기로 사람의 색을 정하고 결과를 표시한다.
  - 판의 빈 교차점을 클릭하면 돌을 놓는다. 마우스를 올리면 돌이 놓일 자리를 미리 보여주고, 마지막에 놓은 돌은 강조한다.
  - AI가 생각하는 동안에는 "AI 생각 중" 표시를 하고 클릭을 막는다.
  - 대국이 끝나면 승자와 이긴 줄을 표시하고, "다시 하기"(같은 난이도), "난이도 변경", "title로" 버튼을 보여준다.
  - 판이 가득 차서 백이 이긴 경우 그 사실을 표시한다.

### 테스트

- 엔진: 승리 판정(가로, 세로, 대각선, 6목 이상, 판 가장자리), 이미 돌이 있는 자리와 판 밖 착수 거부, 판 가득 참, 흑백 결정.
- AI: 하는 즉시 승리와 즉시 방어를 한다. 중은 열린 3을 막는다. 상은 정해진 포석에서 승리 수를 찾는다.
- 난이도 순서: AI끼리 여러 판을 시뮬레이션해서 상이 중을, 중이 하를 대체로 이기는지 확인한다. 흑백을 바꿔 여러 판 둔다. 도구는 Vitest를 쓴다.

## 이후 구현자에게 맡기는 부분

- 오목판의 시각 디자인(색, 돌 모양, 격자선, 반응형 크기)
- 패턴 점수의 구체적인 숫자 값과 후보 칸 개수 등 AI 튜닝값. 난이도 순서 테스트가 통과하는 범위에서 조정한다.
- 폴더 안의 세부 파일 분리, 컴포넌트 분할
- 패키지 관리자 선택(npm 기본)

## 내가 정한 사항 (확인 필요)

- 화면 전환은 라우터 없이 상태로 처리한다.
- 테스트는 Vitest를 쓴다.
- 상 난이도의 시간 제한은 약 1.5초, 최대 깊이는 5(홀수 깊이만)이다.
- 연습 모드의 전적, 대국 기록 저장은 하지 않는다.
- 대국이 끝난 뒤 착수 기록 재생은 이번 범위에서 뺐다. (PRD에는 제안으로 남아 있다.)
