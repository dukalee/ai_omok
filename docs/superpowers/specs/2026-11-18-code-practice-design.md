# 설계: UI 교체(시안 3 + 2)와 "코드로 두기" 연습 모드

이전 설계(`2026-11-18-practice-mode-design.md`, 사람이 직접 AI와 두는 연습 모드)를 대체한다. 규칙 엔진과 AI(하/중/상)는 그대로 쓴다.

## 의도

- 학습자가 연습 모드에서 Python 코드를 직접 작성하고, 그 로직이 AI(하/중/상)와 자동으로 대국하는 것을 보며 고친다.
- 토너먼트에서 같은 코드가 같은 방식으로 실행되므로, 연습 모드가 곧 토너먼트 예행연습이 된다. 코드 실행 파이프라인(Python 실행, 상태 전달, 오류 처리)을 이번에 만들어 토너먼트에서 재사용한다.
- 화면은 시안 3(대국장: 어두운 방, 호두나무 판, 금색)에 시안 2(코드 에디터: 에디터, 실행 버튼, 로그 창, 고정폭 글꼴)를 섞는다.

## 목표

- title 페이지에서 연습 모드로 들어가 코드를 작성하고 실행하면, 상대 AI와 한 판이 끝까지 자동으로 진행된다.
- 진행 과정(착수 순서, 금수 ×, 이긴 줄)이 판 위에 표시되고, 오류와 반칙은 로그 창에 이유와 함께 나온다.
- 코드 실행이 화면을 멈추지 않고, 무한 루프 코드도 시간 제한으로 끊긴다.
- 학습자 코드를 호출하는 부분이 AI 호출과 같은 모양이라서 토너먼트에서 그대로 쓸 수 있다.

## 목표가 아닌 것

- 사람이 직접 클릭해서 두는 모드는 없앤다. (사용자 결정)
- 토너먼트, Supabase, 관리자 기능은 이번 범위가 아니다. 토너먼트 버튼은 "준비 중"을 유지한다.
- 다른 학습자 코드와 대결, 코드 저장 서버, 계정은 없다. 코드는 브라우저(localStorage)에만 저장한다.

## 피해야 할 결과

- 학습자 코드의 무한 루프나 오류가 화면을 멈추거나 앱을 깨뜨리는 것
- 오류 메시지가 Python 내부 용어 그대로 나와서 학습자가 무엇을 고쳐야 할지 모르는 것
- 시안 3과 2가 따로 놀아서(어두운 방에 밝은 에디터가 떠 있는 식) 한 화면으로 보이지 않는 것

## 제약

- React, Vite, TypeScript. 규칙은 `game_rules.md`(렌주 룰). 서버가 없다.
- Python은 브라우저에서 Pyodide로 실행한다(PRD의 제안 방식).

## 접근 방식

1. **Pyodide + Web Worker (선택)**: 서버 없이 동작하고 학습자 코드가 앱과 격리된다. 첫 실행에 Pyodide(약 10MB)를 내려받아 수 초 걸리고, 오프라인에서는 첫 로딩이 안 된다.
2. Python 서버(별도 백엔드): 로딩은 빠르지만 서버 운영과 코드 격리를 따로 해결해야 하고, 지금 구조(정적 앱)와 맞지 않는다.
3. JavaScript로 작성하게 하기: 가장 가볍지만 "학습자는 `.py`를 제출한다"는 전제와 어긋난다.

선택은 1번이다. 이 선택은 사용자가 정한 것이 아니라 PRD의 제안과 현재 구조에 맞춰 내가 고른 것이다.

## 설계

### 학습자 코드 규약 (토너먼트와 공통)

클래스 없이 **함수 하나**로 작성한다. 파일 맨 위 단계에 `play(state)` 함수가 있어야 한다. 시스템이 내 차례마다 이 함수에 판 상태(`state`)를 넘기고, 함수가 반환한 `(행, 열)` 위치에 돌을 놓는다.

```python
def play(state):
    board = state["board"]
    for r in range(15):
        for c in range(15):
            if board[r][c] == 0:
                return (r, c)
```

- 반환값은 `(행, 열)`이다. 리스트 `[행, 열]`도 받는다. 그 외 형태(숫자 하나, `None` 등)는 오류 안내와 함께 패배 처리한다.
- 파일 안에 다른 함수, 변수, `import`를 자유롭게 쓸 수 있다. 전역 변수는 한 판 동안 유지되고(이전 수를 기억하는 용도), 실행할 때마다 처음부터 다시 시작한다.
- 선수 이름은 항상 "Player"로 표시한다. (사용자 결정: 이름을 정하는 `NAME` 변수는 없다)
- 둘 수 있는 자리 목록은 주지 않는다. (사용자 결정) 학습자가 `state["board"]`를 보고 빈 칸을 찾고, 흑은 금수 자리를 스스로 피해야 한다. 금수 자리에 두면 반칙패이다.

`state`(딕셔너리)에는 다음 두 항목만 담는다. 모든 값은 복사본이라서 바꿔도 실제 판에 영향이 없다.
- `board`: 15×15 리스트. `0` 빈 칸, `1` 내 돌, `2` 상대 돌 (항상 내 관점)
- `last_move`: 상대가 마지막으로 둔 `(행, 열)`. 첫 수면 `None`

### 실행 구조

```
src/engine   규칙 (기존)            src/ai   AI (기존)
src/runner   대국 진행 (신규, React 무관)
  - PlayerAdapter: { choose(state): Promise<Move> }
  - runGame(adapters, options): 차례대로 수를 받아 검증하고 이벤트를 방출한다.
    잘못된 수/금수/예외는 그 플레이어의 패배로 끝낸다. 시간 초과도 그 플레이어의 반칙패이다.
  - state 만들기(내 관점으로 변환), AI를 PlayerAdapter로 감싸기
src/python   Python 실행 (신규)
  - pyodide.worker.ts: Pyodide 로드, 학습자 코드 실행(`play` 함수 등록), play(state) 호출, 결과/오류 반환
  - PythonPlayer: Worker를 PlayerAdapter로 감싼다. 시간 초과 시 Worker를 종료한다.
src/ui       화면 (교체)
```

- `runGame`은 이벤트(`start`, `move`, `error`, `end`)를 콜백으로 알린다. 화면은 이를 받아 그리고, 토너먼트 구현에서는 같은 이벤트를 DB에 기록하는 데 쓴다.
- 한 수당 시간 제한은 기본 2초다. (내가 정함. 첫 호출의 Pyodide 로딩 시간은 포함하지 않는다.) 시간 초과면 Worker를 종료하고 학습자 반칙패로 끝낸다.
- 한 번의 실행(한 판)은 하나의 Worker를 쓰고, 끝나면 정리한다. 실행 중에 "중지"를 누르면 Worker와 대국을 취소하고, 이전 실행의 이벤트는 화면에 반영되지 않는다.
- 상대 AI는 기존 하/중/상을 그대로 쓴다(상은 기존 Worker).

### 화면

- **title:** 시안 3. 어두운 방, 조명, 금색 "오목", 작은 판, "연습 모드"(대국장 입장) 버튼과 비활성 "토너먼트 · 준비 중".
- **연습 모드 (코드로 두기):** 왼쪽에 코드 에디터, 오른쪽에 판과 대국 정보. 좁은 화면에서는 위아래로 쌓는다.
  - 에디터: CodeMirror 6(Python 문법 강조). 시안 2의 밝은 에디터를 어두운 방 위의 "종이 패널"처럼 둬서 호두나무 판과 어울리게 한다. 글꼴은 JetBrains Mono. 처음에는 예제 코드가 들어 있다. 코드는 localStorage에 자동 저장되고, "reset"(예제로 되돌리기)이 코드 카드 제목줄 오른쪽에 있다.
  - 컨트롤: 내 색(흑/백/코인), 상대 AI(하/중/상), 진행 속도, "실행", "중지".
  - 대국 정보: 두 선수 이름판(나의 코드 · 흑/백, AI · 하/중/상), 현재 수 번호.
  - 판: 시안 3의 호두나무 판. 마지막 수 강조, 이긴 줄 강조, 반칙으로 진 경우 그 자리에 ×.
  - 로그 창(시안 2): 착수 기록과 안내를 고정폭으로 보여주고, 오류는 빨간색이다. 메시지는 학습자 눈높이로 쓴다. 예: `play()가 (15, 3)을 반환했습니다. 판 밖입니다.` / `play()가 1초 안에 끝나지 않았습니다.` / Python 예외는 줄 번호와 메시지.
- 규칙 안내(`state` 설명)는 에디터 위의 접히는 도움말로 둔다.

### 파일 변경

- 삭제: `src/ui/PracticePage.tsx`의 사람 직접 두기 로직 (새 `PracticePage`로 교체)
- 수정: `Board.tsx`는 시안 3 스타일의 읽기 전용 판으로 단순화한다(클릭, 호버 고스트 제거, 금수 × 표시는 반칙 표시용으로 재사용), `TitlePage.tsx`, `App.tsx`, `ui.css`
- 신규: `src/runner/*`, `src/python/*`, `src/ui/CodeEditor.tsx`, `src/ui/LogPanel.tsx`
- 의존성 추가: CodeMirror 6(`@codemirror/*`, `@uiw/react-codemirror` 등 최소 구성), 글꼴 `@fontsource/gowun-batang`, `@fontsource/jetbrains-mono`, 테스트용 `pyodide`(Node에서 Python 하네스 검증)
- Pyodide 본체는 앱 번들에 넣지 않고 CDN(jsdelivr)에서 Worker가 내려받는다.

### 테스트

- `runGame`: 가짜 PlayerAdapter로 정상 진행, 잘못된 칸/판 밖/금수/예외/시간 초과가 각각 그 플레이어의 패배로 끝나는지, 5목 승리와 판이 가득 차면 백 승리, 취소 시 이벤트가 더 나오지 않는지.
- state 변환: 흑/백 모두 내 관점(1=내 돌)으로 바뀌고, `legal_moves`가 없으며(Python에는 board와 last_move 두 항목만), 복사본을 바꿔도 실제 판이 안 바뀌는지.
- Python 하네스(Node의 `pyodide`): 예제 코드가 유효한 수를 반환, `play` 함수가 없으면 안내 오류, 문법 오류와 예외에 줄 번호가 포함, `play`가 `(행, 열)` 형태가 아닌 값을 반환하면 안내 오류, 전역 변수가 한 판 동안 유지되고 다음 실행에서는 초기화되는지.
- 화면은 Playwright로 수동 확인: 예제 코드 실행, 무한 루프 코드가 시간 초과 반칙패로 끝나는지, 실행 도중 중지/다시 실행, 반칙 표시, 모바일 폭.

## 이후 구현자에게 맡기는 부분

- 색, 간격, 글꼴 크기 등 시안 3과 2를 합치는 세부 스타일(두 시안의 분위기가 이어지게)
- 예제 코드의 내용(유효한 수를 두는 가장 단순한 예)과 로그 문구의 세부 표현
- CodeMirror 확장 구성(최소 구성으로 충분)
- 진행 속도 선택지의 값

## 내가 정한 사항 (확인 필요)

- Python 실행은 Pyodide(브라우저)이다. 첫 실행에 수 초가 걸린다.
- 학습자 코드는 클래스가 아니라 함수이고, 함수 이름은 `play`이다. (사용자 결정: 처음 제안한 `play`에서 `play`로 변경)
- `state`에는 `legal_moves`를 넣지 않는다. (사용자 결정)
- 한 수 제한 시간은 2초이다. 예외, 잘못된 수, 금수, 시간 초과는 학습자 패배이다.도 반칙패이다. (한때 대신 두는 규칙이었으나 사용자 결정으로 되돌렸다)
- 코드는 localStorage에만 저장한다.
- 글꼴은 CDN이 아니라 npm 패키지(@fontsource)로 포함한다.
- 사람 직접 두기는 제거한다.
